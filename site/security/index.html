Security

Private by design, fail-closed by default

Oh My Pi (coding-agent client) connects through OMP NInfer (qualified appliance and release layer) to NInfer (inference engine) serving Qwen3.8 27B (served model) on hardware you own. Your prompt, transcript, and checkpointed continuation state stay local: runtime listeners bind loopback only, every request carries a bearer key, and an unreachable GPU fails the turn instead of answering from a cloud model.

Verified on published v0.15.0 (2026-10-30, stock Oh My Pi 18.14.0): fail-closed behavior is proved in release acceptance across all three client platforms, not assumed from configuration. Full model: docs/SECURITY.md.

Security boundary and release invariants

  • Single trusted ownerEvery published release supports one trusted owner controlling both the Oh My Pi client and the qualified RTX runtime host. Local administrators and root are inside the trust boundary; shared shell hosts, hostile local users, public HTTP exposure, and multi-tenant isolation are outside the release claim.
  • Loopback-only listenersOn the RTX 5090 container lane, Docker runs with --cap-drop ALL, no-new-privileges, and the hash-pinned io_uring seccomp profile (examples/manual-tunnel/ninfer_io_uring_seccomp.json), publishing the server port only on host loopback (127.0.0.1:18089). On the native Windows RTX 4090 and RTX 3090 lanes, the server binds 127.0.0.1:18082 directly on the host (one native lane runs at a time). The macOS preview client reaches the RTX 5090 host only through an authenticated manual SSH local forward (-L 127.0.0.1:18089:127.0.0.1:18089).
  • Bearer authenticationEvery status, Responses, checkpoint, and stored-response route requires a random bearer key stored in access-restricted key files (mode 0600 on POSIX and WSL2; Administrators and SYSTEM ACLs under %ProgramData%\omp-ninfer-keys\api-key.txt and user-only icacls.exe ACLs on native Windows), never committed or embedded in YAML.
  • Fail closed, never cloud fallbackExplicit local provider routes disable retries, model fallback, and automatic client self-updates (examples/manual-tunnel/fail-closed.yml). If the local lane or SSH tunnel is unavailable, the request stops rather than silently escaping to a hosted model.
  • Everything hash-pinned and origin-authenticatedStock Oh My Pi client binaries, the shared Qwen3.8 27B model container version 3 artifact (81f924d4 across all three lanes), container image (@sha256:), native packages, SPDX and CycloneDX dependency SBOMs, server binaries, and configurations are bound in releases/v0.15.0/manifest.json. Checkpoints live in owner-restricted local NVMe directories with HMAC origin authentication (manifest.mac; mandatory --session-checkpoint-require-origin-auth on RTX 5090 schema 3 /checkpoints-v013 and native session-checkpoints-v3), not encryption.

Artifact verification and vulnerability reporting

From a clean clone of the current release tag, verify compatibility.json, the release manifest, and release invariants before starting a lane (exits 0 on a valid ready manifest):

python3 scripts/verify_release.py --require-ready

Report suspected vulnerabilities privately through GitHub private vulnerability reporting (never a public issue). Full threat model and support policy: docs/SECURITY.md · SECURITY.md · release status.

Stopping a container or native lane retains the model artifact, bearer key, checkpoint store, request logs, and Oh My Pi transcripts on disk; delete them explicitly when decommissioning a host.
