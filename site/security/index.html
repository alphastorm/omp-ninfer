Security

Private by design, fail-closed by default

Your prompt, transcript, and checkpointed continuation state stay on hardware you own. Both endpoints bind loopback only, every request carries a bearer token, and an unreachable GPU fails the turn instead of answering from a cloud model.

Fail-closed behavior is part of v0.12.1 acceptance (three stock Oh My Pi 18.10.1 clients, live outage check), not a configuration hope. Full model: docs/SECURITY.md.

Security boundary and release invariants

  • Single trusted owner: Every published release supports one trusted owner controlling both the Oh My Pi client and the qualified RTX runtime host. Local administrators and root are inside the trust boundary; shared shell hosts, hostile local users, public HTTP exposure, and multi-tenant isolation are outside the release claim.
  • Loopback-only listeners (127.0.0.1:18089 and 127.0.0.1:18082): On the RTX 5090 container lane, Docker runs with --cap-drop ALL, no-new-privileges, and the hash-pinned io_uring seccomp profile, publishing the server port only on host loopback (127.0.0.1:18089). On the native Windows RTX 4090 and RTX 3090 lanes, the server binds 127.0.0.1:18082 directly on the host (one native lane runs at a time). The macOS preview client reaches the RTX 5090 host only through an authenticated manual SSH local forward (-L 127.0.0.1:18089:127.0.0.1:18089).
  • Bearer authentication: Every status, Responses, checkpoint, and stored-response route requires a random bearer key stored in access-restricted key files (mode 0600 on POSIX and WSL2; Administrators and SYSTEM ACLs under %ProgramData%\omp-ninfer-keys\api-key.txt and user-only icacls.exe ACLs on native Windows), never committed or embedded in YAML.
  • Fail closed, never cloud fallback: Explicit local provider routes disable retries, model fallback, and automatic client self-updates (examples/manual-tunnel/fail-closed.yml). If the local lane or SSH tunnel is unavailable, the request stops rather than silently escaping to a hosted model.
  • Everything hash-pinned and origin-authenticated: Stock Oh My Pi 18.10.1 binaries, lane-specific Qwen3.8 27B model artifacts (0634abb0 on RTX 5090; eec39564 on native lanes), container image (@sha256:), native packages, server binaries, and configurations are bound in releases/v0.12.1/manifest.json. Checkpoints live in owner-restricted local NVMe directories with HMAC origin authentication (manifest.mac), not encryption.

Artifact verification and vulnerability reporting

From the exact release tag (v0.12.1), verify the manifest, compatibility output, and release invariants before starting a lane:

python3 scripts/verify_release.py --require-ready

Report suspected vulnerabilities privately through GitHub private vulnerability reporting (never a public issue). Full threat model and support policy: docs/SECURITY.md · SECURITY.md · v0.12.1 release status.
