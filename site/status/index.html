Native two-GPU sequential topology and rollback

  • One native lane at a time on port 18082: Both native Windows lanes install on one two-GPU Windows 11 host (RTX 4090 at index 0, RTX 3090 at index 1), each bound to its own GPU UUID and PCI address. Only one native lane runs at a time on authenticated loopback port 127.0.0.1:18082 (within the active RTX 3090 lane, up to two requests run concurrently over one shared 131,072-token INT8 pool). This is not multi-GPU inference and not simultaneous RTX 4090 and RTX 3090 serving.
  • Direct running-lane native upgrade and rollback: In v0.16.2–v0.19.0 (v0.8.0-qwen38-3090-beta.4 and carried v0.8.0-qwen38-4090-beta.3 in v0.19.0), Install-Release.ps1 stops a running incumbent lane through its own controller and hands off the host GPU-ownership lock across power-cap transitions, closing #94 and retaining v0.8.0-qwen38-3090-beta.3 as previous_release for Control-Release.ps1 -Action Rollback on RTX 3090 (while an existing v0.18.0 RTX 4090 beta.3 install already matches v0.19.0 and needs no runtime reinstall, and Control-Release.ps1 restores the GPU-ownership lock if -Action Stop is refused). Keep prior checkpoint roots untouched for rollback and let OMP replay transcripts for fresh sessions.

Client scope and operating boundaries

  • Stock Oh My Pi client: Unmodified upstream release assets (omp-darwin-arm64 2b1309b0, omp-windows-x64.exe 1b6c7bda, omp-linux-x64 c8694be8) pinned in client-components.json. Stock OMP has no omp appliance commands; model fragments set per-model compat.statefulResponses: true, PI_OPENAI_STATEFUL must be absent, and examples/manual-tunnel/fail-closed.yml limits in-flight requests per provider (2 on RTX 5090 and native RTX 3090, 1 on native RTX 4090).
  • macOS preview: The macOS arm64 client reaches the Windows RTX 5090 container over a manual authenticated SSH local forward (127.0.0.1:18089); it remains preview without a managed client installer or appliance lifecycle wrapper.
  • Linux under WSL2: Live Linux-client qualification ran on Ubuntu under WSL2 against the local RTX 5090 container, not on a separately qualified non-WSL Linux OS.
  • Durability and checkpoints: Checkpoints restore after a server restart on all three lanes only when the runtime binary, model artifact, deployment profile, and session credentials match. Saves remain best effort under live traffic (a crash or expired graceful wait can lose unsaved work), and universal warm reuse is not promised. Checkpoint transport and NAS replication.
