What it does

A long coding session is 100K tokens of transcript, thinking, tool calls, and images. Sent to a cloud provider, every token is metered and every file leaves your machine. Sent to a stateless local server, every turn re-sends the whole transcript.

A live NInfer, llama.cpp, or vLLM process already avoids recomputing an unchanged prefix while it stays up; that is prior art, and this project does not claim it. What OMP NInfer adds is continuation you can rely on.

  • Explicit and durable

    Oh My Pi drives NInfer through stateful OpenAI Responses (previous_response_id); forks and rollback are qualified, and checkpoints restore after a server restart. Oh My Pi commits the transcript first, so losing retained state degrades to a replay, never a broken session.

  • Private and fail-closed

    Runtime listeners bind loopback only, every request is bearer-authenticated, and model fallback is off: an unreachable GPU fails the turn instead of answering from a cloud model. This is acceptance-tested, not configured.

  • Exact and verifiable

    Model SHA-256, container digest and SBOM, native package and client checksums, and every qualification receipt are bound in one manifest; python3 scripts/verify_release.py --require-ready proves your clone is the qualified release.

How it fits together

Who owns what.

Oh My Pi owns the conversation transcript, tools, coding workflow, and subagents. NInfer's single-GPU engine keeps your session's continuation state resident on your GPU; OMP NInfer is the qualified release that binds them without a forked client or an extra gateway.

  1. Coding-agent clientOh My Pi

    Owns the transcript, tools, forks, and replay. Commits locally before provider state advances.

  2. Qualified appliance and release layerOMP NInfer

    Setup, release manifests, hardware profiles, qualification, security boundaries, and support. No duplicated OMP or NInfer implementation.

  3. Inference engineNInfer

    Neroued's single-GPU engine and its GPU ports. The shipped NInfer runtime adds explicit OpenAI Responses continuation state (previous_response_id) and durable local NVMe checkpoints.

  4. Served modelQwen3.8 27B

    One hash-pinned artifact, 20.4 GB 81f924d4, identical across all three qualified lanes.

Commit boundary: complete stream → durable transcript → provider state. One truth, one accelerator, no hidden gateway.

  • Loopback onlyThe runtime binds 127.0.0.1:18089 (RTX 5090 container) or 127.0.0.1:18082 (native Windows lanes); remote macOS clients reach the host through an authenticated SSH local port forward.
  • Bearer-authenticatedEvery status, Responses, checkpoint, and stored-response route requires a random bearer key kept in access-restricted key files, never committed or embedded in YAML.
  • Fail-closed, never cloud fallbackExplicit local provider routes disable retries, model fallback, and automatic client self-updates; an unavailable lane stops the request instead of escaping to a hosted model.
  • Every byte hash-pinnedStock Oh My Pi client binaries, the model artifact, container image, native packages, SBOMs, server binaries, and configurations are bound in the release manifest.

Durability

Checkpoints already leave the machine.

Checkpoints restore after a server restart on all three qualified lanes, and scripts/checkpoint_sync.py exports and imports verified checkpoint generations across local storage and off-machine replicas. Network shares are replica storage, never the live checkpoint root.

Restore requires the same runtime binary, model artifact, serving profile, and session credentials; checkpoint saves remain best effort under live traffic, and universal warm reuse is not promised. Oh My Pi's transcript remains the source of truth, so losing retained state degrades to a transcript replay rather than cloud fallback. Scope, usage, and receipts.

Is it for you

The narrow target is what makes the recommendation credible.

Every project below is excellent at a different job. The comparison makes that call fast and candid, without self-assigned scores or rankings.

Use it when

  • You use Oh My Pi and own an eligible RTX 5090, RTX 4090, or RTX 3090 setup matching the exact release profile.
  • Qwen3.8 27B is the model you want, running privately on hardware you own.
  • Coding sessions are long-lived, and explicit continuation across inference-server restarts matters more than model catalog breadth.

Use something else when

  • You want a broad model catalog: Ollama.
  • You want a desktop GUI: LM Studio.
  • You want the widest hardware reach or Apple silicon: llama.cpp.
  • You want multi-user throughput: vLLM.

The 0.x series supports only the latest published release and its exact manifest and profiles. Manifest · release notes · compatibility.
